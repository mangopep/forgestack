# Review quality bar
Review for correctness, data integrity, race conditions, access control, unsafe defaults, error handling, resource leaks, backward compatibility, reliability, operational visibility and costs.
Prioritize reproducible findings with file/line references, impact and concrete fixes; label severity Critical/High/Medium/Low. Avoid superficial style-only reviews.
Review changes against acceptance criteria, tests, README and rollback path. Explicitly say when a category was not checked. Reviewer must not change code unless user separately requests a fix.
